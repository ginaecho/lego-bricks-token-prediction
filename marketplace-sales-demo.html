Show the LEGO-style estimator and evidence boundary

The atomic coefficients are reused from the original marketplace demo. Variant task repetitions, model factors, staffing hours and tool fees are illustrative extensions. No runtime, research depth, or outcome is validated.

Atomic taskInput tokensOutput tokens

Per variant input = ceil((sum of atomic input + context + custom-brief characters / 4) × scenario input factor). Output = ceil(sum of atomic output × scenario output factor). Multiply each by its own monthly runs, then rate the input and output separately.

Between distinct selected capabilities, each pair routes min(left runs, right runs) times. Routing uses 120 input + 30 output tokens per paired run. Each pair adds 18,000 input + 6,000 output setup tokens, plus 4 architect and 4 consultant setup hours. Integration complexity scales those amounts. The team behind the build

Setup hours are summed once across selected variants. FTE = role hours / (delivery weeks × hours per week). People = rounded-up FTE; fractional workloads can be shared across projects. Changing the timeline changes capacity, not total labor cost.

Token yield / the client value case

What is a better outcome worth?

Count unique client cases once, not once per brick. A workflow can invoke several variants; benefits are not automatically multiplied when adding capabilities.

Time released = unique cases × (before − after) / 60. Monthly gross benefit = time released × labor value × realized share + incremental contribution. Negative time savings remain negative. Zero selected workloads or zero client cases produce no benefits.

What must be proven with the client?

Productivity, without quality loss

Measure minutes per accepted case, reviewer effort, rework, and acceptance rate against the manual baseline. Validate whether released capacity is redeployed or removed.

Better customer experiences

Test conversion, useful recommendations, customer satisfaction and retention against a control. Add incremental contribution only when supported by evidence.

Capacity & reliability

Validate throughput, latency, provider limits and failure rates. Selected workload counts are not a service-level guarantee.

Responsible resource use

Measure energy per accepted outcome and sensitive-data handling. Token savings alone do not prove carbon savings, quality or ROI.
